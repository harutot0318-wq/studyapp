0. 3種類のファイルという考え方

47ファイルありますが、実際には3つの役割の組み合わせでほぼ全部説明がつきます。まずこれを頭に入れておくと、以降の一覧が読みやすくなります。

役割ファイル名の目印やること動く場所
画面page.tsxデータを取得して、HTMLとして表示するサーバー
データ取得queries.tsデータベースから「読み取る」だけの関数を置く場所サーバー
データ更新actions.tsフォーム送信を受けてデータベースを「書き換える」関数（Server Actions）サーバー

機能ごとの各フォルダ（tasks/、materials/など）は、基本的に page.tsx（画面）とactions.ts（更新処理）の2ファイルで完結していて、読み取り専用の関数だけはlib/側のqueries.tsにまとめてある、という配置になっています。「読み取り（lib/*/queries.ts）」と「書き込み（app/(app)/*/actions.ts）」を別の場所に置いているのは、読み取り関数はダッシュボードなど複数の画面から使い回すことがあるためです（例：lib/tasks/queries.tsのgetTasks()は、タスク管理画面とダッシュボードの両方から呼ばれています）。

1. app/ 配下 ― 画面とルーティング

Next.jsではapp/フォルダの中のフォルダ構造がそのままURLになります。例えばapp/(app)/tasks/page.tsxは/tasksというURLに対応します。(app)のようにカッコで囲まれたフォルダ名は「URLには影響しないグループ分け」という特殊な意味を持ちます（詳しくはコード解説書参照）。

app/(app)/layout.tsx レイアウト

app/(app)/page.tsx 画面（"/"）
ダッシュボード。今日/今週の学習時間・連続学習日数・目標達成率・タスク一覧・最近の学習記録をまとめて表示する。複数のlib/*/queries.tsを呼び出して集計結果を並べているだけで、専用の更新処理（actions.ts）は持たない（このページから直接データを書き換えることはないため）。

3. lib/ 配下 ― データ処理・ユーティリティ (16ファイル)

画面には出てこない「裏方」の処理をまとめたフォルダです。特にqueries.tsという名前のファイルが並んでいますが、これは全て「データベースから読み取るだけ」の関数の置き場所という共通ルールになっています。

3.1 lib/supabase/ ― データベースへの接続設定

5. 1機能が実際にどうファイルをまたぐか（3つの実例）

例1：タスクを追加するとき

ユーザーがフォーム送信
  → app/(app)/tasks/actions.ts の createTask() が実行される
    → lib/supabase/server.ts の createClient() でDB接続を作る
    → tasksテーブルにINSERT
    → revalidatePath("/tasks") で画面のキャッシュを無効化
  → app/(app)/tasks/page.tsx が再実行される
    → lib/tasks/queries.ts の getTasks() で最新の一覧を取得
    → 画面に反映

例2：ダッシュボードを開いたとき

app/(app)/page.tsx が呼ばれる
  → lib/exams/active.ts          getActiveExam()        今の資格を特定
  → lib/dashboard/queries.ts     getDashboardStats()     学習時間・連続日数を集計
  → lib/tasks/queries.ts         getTasks()              今日のタスク
  → lib/study-logs/queries.ts    getRecentStudyLogs()    最近の記録
  → lib/goals/queries.ts         getGoals()               目標達成率
  ↑ これら5つの関数の結果を1画面にまとめて表示している

ダッシュボードは「新しいデータを作る」画面ではなく「あちこちのデータを集めて見せる」画面なので、actions.tsを持たず、複数のqueries.tsを呼ぶだけになっているのがポイントです。

例3：資格を切り替えたとき

「この資格に切替」ボタン
  → app/(app)/exams/actions.ts の setActiveExam()
    → Cookie「active_exam_id」に選んだ資格のIDを保存
  → 以後どの画面を開いても
    → lib/exams/active.ts の getActiveExam() がそのCookieを読み、
      「今の資格」として扱う

6. 命名・配置のルールまとめ

  • page.tsx：そのフォルダのURLに対応する画面。1つのフォルダに1つだけ
  • actions.ts：そのページのフォームから呼ばれる、データベースを書き換える関数。ファイル冒頭に"use server"
  • queries.ts：lib/機能名/に置く、データベースから読み取るだけの関数。複数の画面から使い回される
  • "use client"が付いているファイル：ブラウザ側で動く必要がある部品だけ（グラフ、サイドバーの現在地表示）。それ以外は全部サーバー側で動く
  • 機能ごとにフォルダを分ける：「資格」「タスク」「単語」のようにドメインでフォルダを切ることで、1つの機能に関係するファイルが近くにまとまり、影響範囲が把握しやすくなる
