資格勉強向け学習管理アプリ 技術選定書

作成日：2026年7月23日　／　対象：要件定義書（2026年7月23日版）に基づく技術選定

1. 本書の位置づけ

本書は「資格勉強向け学習管理アプリ 要件定義書」に記載された機能要件・非機能要件を実現するにあたり、採用する技術スタックを選定し、その根拠を整理したものである。 開発体制は個人開発（一人）を前提とし、インフラ方針は特定の希望がないため、要件（個人利用中心・拡張性重視・毎日使う簡便さ）に最も適した構成をこちらで提案する。

2. 選定方針・評価基準

要件定義書から、技術選定において特に重視すべき点を以下のとおり整理する。

  • 個人開発での運用負荷の低さ：インフラ管理・保守を一人でまかなえること
  • 学習・実装コストの低さ：機能実装のスピードを優先し、枯れた技術・情報量の多い技術を選ぶこと
  • 拡張性：AI解説・通知・グラフ分析・バッジ機能など将来拡張を後付けしやすいこと
  • レスポンシブ対応：PC・スマートフォン双方のブラウザで閲覧・操作できること
  • データの継続性・可用性：学習履歴や単語帳データが消失しないこと
  • 費用：個人開発のため、無料枠または低コストで運用開始できること

各評価項目は ◎（優れる）／〇（妥当）／△（やや弱い） の3段階で比較する。

3. 技術比較

3.1 フロントエンドフレームワーク

候補学習コスト情報量・実績UI実装効率拡張性備考
Next.js（React + TypeScript）〇◎◎◎フロント・API・SSRを一体で扱え、Vercelとの親和性が高い
Nuxt（Vue + TypeScript）◎〇〇〇学習コストは低いが、周辺ライブラリ（グラフ・UIキット等）はReact系がやや優勢
SvelteKit◎△〇△軽量で書きやすいが、情報量・実績が少なくBaaS連携例も少ない

採用：Next.js（React + TypeScript）採用
理由：ダッシュボード・学習分析・単語検索など画面数が多く状態管理が複雑になるため、型安全なTypeScriptと情報量の多いReactエコシステムが個人開発でのトラブル解決速度に直結する。後述のBaaS（Supabase）・ホスティング（Vercel）との連携実績も豊富。

3.2 バックエンド／インフラ方針

候補実装コスト運用負荷拡張性費用備考
BaaS（Supabase）◎◎〇◎認証・DB・ストレージ・Edge Functionsを一体提供。個人開発向け無料枠あり
BaaS（Firebase）◎◎〇〇NoSQL（Firestore）中心。学習記録・分析など集計処理はRDBの方が扱いやすい
自前バックエンド（Node.js等 + クラウド）△△◎〇自由度は最も高いが、認証・インフラ構築・保守を一人で担う負荷が大きい

採用：Supabase（BaaS）採用
理由：学習記録・教材・単語帳・復習管理はいずれもリレーショナルなデータ構造（科目⇄教材⇄単語のような紐付け）と相性がよく、PostgreSQLベースのSupabaseが適する。認証・DB・ファイルストレージ・定期実行（復習リマインダー等の将来拡張）を単一サービスでカバーでき、個人開発での運用負荷を最小化できる。

3.3 データベース

候補データ構造適合集計・分析のしやすさ備考
PostgreSQL（Supabase標準）◎◎科目・教材・単語・復習の関連データをリレーションで表現しやすく、学習分析のSQL集計も容易
Firestore（NoSQL）〇△柔軟だが、科目別・教材別の集計や絞り込み検索の実装がやや複雑になりやすい

採用：PostgreSQL採用（3.2の選定に付随して決定）

要件定義書4.1の決定（資格 → 科目 → 教材 → 単語の階層構造、複数資格の並行管理）を踏まえ、exams（資格）を親とし、subjects（科目）・materials（教材）・words（単語）が外部キーで連なるテーブル構成とする。各テーブルはuser_idを持ち、Supabaseの Row Level Security（RLS）で利用者ごとのデータ分離を行う。この構成はリレーショナルDBであるPostgreSQLと親和性が高く、3.2の選定理由（リレーショナルなデータ構造との相性）を裏付ける形となる。

3.4 認証

候補実装コスト将来のマルチデバイス同期備考
Supabase Auth（メール／SNSログイン）◎◎DBと統合済みで追加実装がほぼ不要。今後の検討事項「認証方式」にも対応可能
自前認証実装△〇パスワード管理・セキュリティ対応を自前で担う必要があり、個人開発では負荷が大きい

採用：Supabase Auth採用（初期リリースからメールログインに加えGoogleログイン等のSNSログインも実装する。Supabase AuthのOAuthプロバイダ設定で追加実装コストを抑えられる）

3.5 ホスティング／デプロイ

候補Next.jsとの親和性運用負荷費用備考
Vercel◎◎◎Next.js開発元が提供。個人利用は無料枠内で運用可能。デプロイが自動化されている
AWS（Amplify等）〇△〇拡張性は高いが設定項目が多く、個人開発では運用負荷が相対的に高い

採用：Vercel採用
理由：Next.jsとの統合が最も簡便で、Gitリポジトリへのpushで自動デプロイが可能。個人開発の運用負荷を抑えられる。

3.6 UIスタイリング

候補実装速度レスポンシブ対応備考
Tailwind CSS◎◎ダッシュボード等の細かいレイアウト調整がしやすく、レスポンシブ対応もユーティリティクラスで完結
CSSフレームワーク（Bootstrap等）〇〇コンポーネントは充実するが、独自デザインの細かい調整はTailwindより手間がかかる

採用：Tailwind CSS採用

3.7 グラフ・分析（学習分析機能向け）

候補React親和性実装コスト備考
Recharts◎◎科目別・教材別の学習時間集計、推移グラフ（4.10 学習分析）をシンプルに実装可能
Chart.js〇〇機能は豊富だがReact向けラッパーが一枚挟まる分、実装がやや冗長になりやすい

採用：Recharts採用

3.8 将来拡張（通知・AI解説）に向けた方向性

拡張機能想定技術備考
復習リマインダー通知Web Push（Service Worker）＋ Supabase Scheduled Functionsブラウザ標準機能で完結でき、追加インフラが不要
AIによる単語解説Anthropic API または OpenAI API単語帳データを渡してAPI経由で解説文を生成。Supabase Edge Functions経由での呼び出しを想定
バッジ・実績機能アプリ内ロジック（DBフラグ管理）新規サービス導入は不要。既存DBスキーマの拡張で対応可能

5. アーキテクチャ概要

  • ブラウザ（PC／スマートフォン）→ Vercel上のNext.jsアプリ（画面表示・API Routes）
  • Next.js（API Routes／Server Actions）→ Supabase（認証・DB・ストレージ）へアクセス
  • 復習リマインダー等はSupabaseのScheduled Functionsから定期実行し、Web Pushでブラウザへ通知（将来拡張）
  • AI解説機能は、Next.js（またはSupabase Edge Functions）から生成AI APIを呼び出す構成とする（将来拡張）

6. 費用概算（個人利用規模を想定）

サービス目安費用備考
Vercel無料枠（Hobbyプラン）個人利用のトラフィック規模であれば無料枠内で収まる想定
Supabase無料枠（Freeプラン）DB容量・API呼び出し数が増えた場合はProプラン（月額約$25〜）への移行を検討
生成AI API（将来拡張時）従量課金単語解説の呼び出し頻度に応じた費用が発生。導入時に別途見積もりが必要

7. リスク・今後の検討事項

  • Supabase無料枠の制限（DB容量・帯域）を超えた場合の移行コストを事前に把握しておく
  • スマートフォンからの利用感（レスポンシブ対応の実機確認）を早期に検証する
  • 要件定義書「7. 今後の検討事項」にある認証方式・データエクスポート・通知手段・マルチデバイス同期方式は、本選定（Supabase Auth／Web Push／PostgreSQL）を前提に別途詳細設計で具体化する
  • AI解説機能導入時は、利用するAPIの費用体系とレート制限を踏まえた設計が必要
